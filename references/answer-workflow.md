# 根拠付き定型回答

この経路は、AIが基準の本文を自由生成せず、照会条件に一致した確認済み項目からPythonが回答を組み立てる試作です。大阪市・北海道・日立市の限定した工程を扱います。他の地域は資料索引に残していますが、この経路の回答用データにはしていません。

## 手順

1. `python scripts/answer_criteria.py --list` で対応する照会条件を確認する。
2. 利用者が示した管理者・対象・段階・版・照会項目・範囲をJSONにする。入力にない条件を候補から勝手に選ばない。欠けているキーは省略する。
3. `python scripts/answer_criteria.py --request request.json` で回答JSONを得る。
4. 回答JSONを保存した場合は `python scripts/answer_criteria.py --request request.json --verify answer.json` で検査する。元の照会JSONを維持し、検査を通すために書き換えない。
5. `answer_markdown` を改変せず提示する。直接表示する場合は `--markdown` を使える。

コマンドのパスはskillフォルダから解決する。追加パッケージやAI API、通信は不要。

## 日立市の例

```json
{
  "purpose": "原典記載の照会",
  "issuer": "日立市",
  "facility": "街路樹",
  "stage": "機器診断・優先撤去条件",
  "edition": "令和6年7月",
  "topic": "40%境界",
  "scope": "平和通りのサクラ"
}
```

これは計画の記載を照会する条件であり、対象木の測定値を入力して診断する機能ではない。

## 結果の扱い

|状態|応答|
|---|---|
|reference_only|指定版にある記載を出典付きで提示。現場への適用は確定しない|
|source_conflict|相違する根拠を一緒に提示し、結論を確定しない|
|needs_context|不足条件を確認し、回答を保留|
|not_recorded|確認済み情報は未収録と伝える。別地域・別工程へ自動で広げない|
|unsupported_purpose|個木の安全性や処置の決定は行わない|

`find_criteria.py` とHTMLの検索は資料発見用です。検索候補やカードの要約を、そのまま定型回答の確認済み根拠として扱わないでください。

## 保証できる範囲

検査は指定入力と収録根拠から作る定型回答の完全一致を確かめます。根拠ID、文、数値、リンクの改変や、不一致の片側だけの省略を検知します。任意に書き換えた自然言語の意味の正しさを判定する仕組みではありません。

利用者の自然文をAIが誤ってJSONへ変換した場合、入力を捏造した場合、検査後に文章を書き足した場合までは防げません。回答に照会条件を表示し、利用者が条件を確認できる形にしています。データやコード自体が信頼できることも前提です。ハッシュは改変への署名や原典の正しさの証明ではありません。

原典全体の正確性・最新性・個別契約への適用は別の確認が必要です。下位モデルによる実利用試験は未実施で、今回のテストは検索条件と定型回答プログラムの挙動を対象にしています。

## 根拠の追加

原典の該当箇所を照合し、`evidence.json` のsourcesにURL・版に対応する資料・紙面頁・PDF頁・表や節・取得原本のSHA-256・確認状態を記録します。claimsには主張とsource_idsを付け、routesに管理者・対象・段階・版・照会項目・範囲を指定します。相違する記載と適用除外は、対応routeの必須claimとして一緒に返します。

原典と未照合の項目を自動で昇格させないでください。`python scripts/build_index.py` でmanifestを更新し、`python scripts/test_answer_criteria.py` と `python scripts/validate_sources.py` で検査します。
